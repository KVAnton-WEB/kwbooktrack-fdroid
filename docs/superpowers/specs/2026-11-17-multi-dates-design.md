# Несколько дат: пересмотры фильмов и перечитывания книг

Дата: 2026-11-17

## Зачем

У фильма одна дата просмотра, у книги одна дата дочитывания. Пересмотр и
перечитывание теряются: в календаре видно один раз, в статистике минуты
считаются один раз, а в бэкап уезжает одна дата.

## Что хотим

- Список дат у фильма («просмотрено») и у книги («прочитано»).
- Кнопка «добавить просмотр» / «добавить прочтение» — создаёт ещё одно поле
  даты.
- Все даты видны в календаре.
- В Tellico уходит **одна** дата — самая ранняя.
- В своём zip-бэкапе уходят **все** даты, чтобы импорт их восстановил.

## Решения (приняты с владельцем)

| Вопрос | Решение |
|---|---|
| Даты у книг | Отдельный список «прочитано», как у фильма. Журнал сессий живёт отдельно и в календаре по-прежнему виден |
| Статистика при пересмотре | Считаем **просмотры**: «просмотрено: 2 просмотра», минуты удваиваются |
| Какая дата в Tellico | **Самая ранняя** по календарю |

## Данные

Новая таблица — только **дополнительные** даты. Основная дата остаётся там,
где была: `movies.watched_at` и `books.finished_at`.

```kotlin
@Entity(
    tableName = "media_dates",
    indices = [Index(value = ["media_id"]), Index(value = ["media_type"])],
)
data class MediaDateEntity(
    @PrimaryKey(autoGenerate = true) @ColumnInfo(name = "id") val id: Long = 0,
    @ColumnInfo(name = "media_id") val mediaId: Long,
    @ColumnInfo(name = "media_type") val mediaType: MediaType,
    @ColumnInfo(name = "date") val date: Long,
)
```

**Миграция 11 → 12**: создать таблицу. Переноса данных не нужно — основные
даты остаются в своих колонках, а дополнительных ещё нет. Таблица
`media_dates` ни на что не ссылается, поэтому порядок пересоздания таблиц
(как в 9 → 10) здесь не нужен.

**Основная дата = самая ранняя.** В редакторе список дат отсортирован по дате,
первое поле — самая ранняя, и именно она пишется в `watched_at` /
`finished_at`; остальные — строки в `media_dates`. Из этого следует:

- в Tellico уходит основная дата, то есть **самая ранняя** — требование
  выполнено без изменений в writer'е;
- фильтр списка «Просмотрено» (`watched_at != null`) работает как раньше:
  если есть хоть одна дата, основная заполнена;
- порядок полей в редакторе не «прыгает» после сохранения.

## Экраны

### Редактор фильма

Поле «Просмотрено» превращается в список полей даты + кнопка
«Добавить просмотр». Каждое поле — существующий `DatePickerField`
(значение — строка `dd.MM.yyyy`), у него же есть снятие даты.

Состояние: `MovieEditState.watchedDates: List<String>` вместо
`watchedDate: String`.

### Редактор книги

Чекбокс «Прочитано» остаётся (он ставит статус FINISHED), список дат
показывается при включённом чекбоксе — как сегодня показывается единственное
поле даты. Снятие чекбокса сбрасывает все даты, как сегодня сбрасывается
единственная.

### Карточка фильма и книги

Вместо одной даты — список всех дат (по одной на строку). Даты идут по
возрастанию.

### Календарь

Даёт все даты: основная плюс дополнительные.

- Фильмы: фильм попадает в ячейку каждой своей даты; минуты в ячейке — сумма
  длительностей по просмотрам за этот день. Два просмотра в один день = две
  длительности.
- Книги: даты «прочитано» (основная плюс дополнительные) плюс даты сессий
  журнала — как сейчас.

### Статистика

- Фильмы: просмотр = одна дата. «Просмотрено: N» — число просмотров,
  «Минут просмотра» — сумма длительностей по всем просмотрам. Графики по
  месяцам и годам считают то же самое по каждой дате.
- Книги: «прочитано по месяцам» считает все даты «прочитано». Сессии журнала
  (страницы, сессии) не меняются.

## Выгрузка

### Tellico (`.tc`)

Пишется только основная дата — самая ранняя. Writer не меняется.

Импорт Tellico: одна дата из коллекции → основная дата, дополнительных нет.

### Свой zip-бэкап

- `movies.csv` / `books.csv`: колонка `watched_at` / `finished_at` — основная
  дата.
- `extra.json`: у каждой книги и фильма — список дополнительных дат.

Импорт бэкапа восстанавливает и основную, и дополнительные.

## Что не делаем

- Не трогаем журнал чтения: сессии остаются как были.
- Не меняем формат Tellico: одна дата, как сейчас.
- Не добавляем отдельную сущность «просмотр» с оценкой или заметкой — только
  даты.

## Решения по ходу проверки

Проверку прошёл независимый «строитель» — семь мест, где пришлось бы
угадывать. Все семь закрыты ниже; это мои решения, не ваши (ваши три ответа
выше).

1. **Фильтр по периоду в списке — по любой из дат.** Фильм, посмотренный в
   марте и пересмотренный в мае, должен попасть в список за май. Значит
   `LibraryViewModel` читает `media_dates` и фильтрует по всем датам
   владельца, а не по основной. Таблица маленькая (одна строка на
   дополнительную дату), лишний запрос на список не бьёт по экрану.
2. **Слияние при импорте — объединение дат.** Нынешнее правило «пришедшая
   дата не затирает существующую» сохраняется, но основная дата
   пересчитывается как самая ранняя из объединения. Иначе инвариант
   «основная = самая ранняя» ломался бы после импорта, и в Tellico уехала бы
   не самая ранняя дата. Равные даты при импорте не дублируются.
3. **Две одинаковые даты разрешены** (два просмотра в один день — бывает):
   уникального индекса на дату нет, в редакторе видны два одинаковых поля,
   в статистике это два просмотра, в календаре — две длительности за день.
4. **В ячейке календаря — одна плитка на фильм в день**, как у книг сейчас
   (`distinctBy`). Минуты за день суммируются по всем просмотрам этого дня,
   поэтому «два просмотра» видно по минутам, а не по двум обложкам.
5. **«Отметить прочитанным» на карточке книги добавляет дату**, а не
   заменяет основную: книга, прочитанная в январе и отмеченная прочитанной
   в ноябре, сохраняет январскую дату и получает вторую.
6. **Строки `media_dates` удаляются руками** при удалении книги или фильма —
   по образцу заметок и фото: внешнего ключа нет, чистит DAO в той же
   транзакции (`deleteWithContent`).
7. **Новое поле даты в редакторе пустое** — дату выбирает пользователь (как
   в единственном поле сегодня). У книги список показывается при включённом
   чекбоксе «Прочитано», внутри — пустое поле.

Мелочи, решённые по конвенциям проекта: `media_dates.date` — epoch-миллисекунды
полночи в местной зоне (`data/time/Epoch.kt`), `media_type` — существующим
конвертером `MediaType`, в `extra.json` — новый ключ со списком epoch-миллисекунд
по образцу `SessionJson`, индексы в миграции — `index_media_dates_media_id` и
`index_media_dates_media_type`.
