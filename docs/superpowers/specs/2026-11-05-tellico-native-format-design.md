# Родной формат Tellico (XML / .tc): импорт + экспорт без потерь — design

Date: 2026-11-05
Project: kwbooktrack (Android, Kotlin, Compose, Room, Hilt)
Status: одобрен пользователем (границы задачи), ожидает утверждения документа

## Goal

1. **Импорт**: приложение читает родной формат Tellico — XML (`tellico.xml`
   внутри `.tc`/`.zip`, либо сам `.xml`) — наряду с существующим импортом CSV.
   Формат определяется автоматически по содержимому файла.
2. **Экспорт в `.tc`**: приложение пишет родной `.tc` (`tellico.xml` +
   `images/`), который Tellico открывает штатно. Это и есть синхронизация
   между программами: каталог уходит в Tellico и приходит обратно.
3. **Без потерь**: и `.tc`, и нынешний zip-бэкап (`books.csv`) должны
   переносить **всё** содержимое приложения — включая то, чего в Tellico нет:
   статус `ABANDONED`, сессии чтения, фото заметок, теги, «создано/изменено»
   и чужие поля Tellico (`livelibfantlab`, `посоветовал`, `чтец`…). Повторный
   импорт такого файла в приложение не теряет данные.

## Non-goals (YAGNI)

- Не делаем импорт/экспорт **всех** типов коллекций Tellico (фильмы, игры,
  музыка). Только книги (`collection type="2"`).
- Не переносим в Tellico то, чему в Tellico нет соответствия, «как есть»:
  для таких данных заводим **собственные поля Tellico** (см. §6).
- Не переписываем формат `books.csv` — он остаётся CSV, но рядом с ним
  появляется `extra.json` с недостающими данными (см. §5.7).
- Не трогаем `titleSearch`/`authorSearch`/`seriesSearch` — это производные
  значения, `BookRepository.withSearchKeys()` пересчитывает их при записи.

## Решения, зафиксированные в брейншторме

| Вопрос | Ответ |
| ------ | ----- |
| Что входит в задачу | Импорт **и** экспорт в `.tc` |
| Как называть нестандартные поля Tellico в `.tc` | По-русски, как в коллекции пользователя («Место покупки» и т.д.) |
| Что кладём в `.tc` кроме книг | Книги + обложки + рецензии + цитаты |
| Что ещё должно экспортироваться | `ABANDONED`, сессии чтения, фото заметок, теги, «создано/изменено», чужие поля Tellico — всё без потерь |
| Поведение при повторном импорте | **Слияние без дублей**: новое добавляется, существующее не трогается, дубли не создаются |
| Нынешний экспорт `books.csv` | Тоже сделать без потерь |

## Формат Tellico — что выяснено

`.tc` — это **ZIP**. Внутри:

- `tellico.xml` — сам каталог;
- `images/` — обложки (имя файла совпадает со значением `<cover>`); в других
  раскладках — `<collection>_files/`.

Структура `tellico.xml` (DTD: `http://periapsis.org/tellico/dtd/v12/tellico.dtd`):

```xml
<tellico xmlns="http://periapsis.org/tellico/" syntaxVersion="12">
 <collection title="Мои книги" type="2">
  <fields>
   <field category="Общее" flags="0" format="1" name="title" title="Заголовок" type="1"/>
   <field category="Покупка" flags="0" format="4" name="место-покупки" title="Место покупки" type="3"/>
  </fields>
  <entry id="1">
   <title>Властелин Колец</title>
   <authors><author>Толкин, Джон</author></authors>
   <genres><genre>фэнтези</genre><genre>эпическое фэнтези</genre></genres>
   <pur_date calendar="gregorian"><year>2023</year><month>08</month><day>04</day></pur_date>
   <read>true</read>
   <cover>0dcebf7e7711bd7154db82b21cac7f61.jpeg</cover>
   <comments>…HTML…</comments>
   <цитатыs><цитаты>1::текст цитаты
2::вторая</цитаты></цитатыs>
  </entry>
  <images><image format="jpeg" height="488" id="0dcebf7e….jpeg" width="310"/></images>
 </collection>
 <filters>…</filters>
</tellico>
```

Ключевые наблюдения:

- Внутри `entry` поля называются **внутренними английскими именами**
  (`title`, `authors/author`, `isbn`, `pages`, `languages/language`,
  `genres/genre`, `publisher`, `pub_year`, `cr_years/cr_year`, `series`,
  `series_num`, `condition`, `translators/translator`, `binding`, `pur_price`,
  `pur_date`, `read`, `gift`, `loaned`, `rating`, `cover`, `comments`,
  `cdate`, `mdate`), а **пользовательские поля — своими именами**
  (`место-покупки`, `дата-прочтения`, `рецензия`, `цитаты`, `продано-new`).
  Человеческое название лежит в атрибуте `title` у `<field>`.
- **Многозначные поля (AllowMultiple, т.е. `flags & 1`) пишутся контейнером**
  `имя + "s"`, значения — вложенными элементами `имя`:
  `<authors><author>…</author></authors>`, `<genres>`, `<languages>`,
  `<translators>`, `<cr_years><cr_year>…</cr_year></cr_years>`,
  `<keywords>`. Поля без этого флага плоские: `<publisher>`, `<series>`,
  `<binding>`. У пользователя `цитаты` объявлены с `flags="1"`, поэтому
  Tellico пишет их как `<цитатыs><цитаты>…</цитаты></цитатыs>`, и в одном
  контейнере бывает несколько таблиц (в реальных данных: 36 контейнеров, у
  шести — по 2–4 таблицы).
- Даты — либо `<поле calendar="gregorian"><year/><month/><day/></поле>`, либо
  текстом `2024-04-14`.
- Табличные поля — `страница::текст`, строки разделены `\n`. В **CSV** тот же
  столбец пишется с одиночным двоеточием (`1:текст`).
- Многозначные значения в CSV Tellico пишет через `; `.
- `<field>` требует `category` (в DTD `#REQUIRED`).

## Архитектура

### 5.1 Общая модель: снимок библиотеки

Импорт и экспорт обоих форматов работают с одной моделью — «снимок книги»:

```kotlin
data class BookSnapshot(
    val book: BookEntity,
    val notes: List<NoteSnapshot>,        // вид, страница, текст, createdAt
    val sessions: List<SessionSnapshot>,
    val tags: List<String>,
    val photos: List<PhotoSnapshot>,      // файл в архиве, индекс заметки, createdAt
    val extraFields: Map<String, ExtraField>, // чужие поля Tellico: имя → (title, value)
)

data class NoteSnapshot(val kind: NoteKind, val body: String, val page: Int?, val createdAt: Long?)
data class SessionSnapshot(val startedAt: Long, val endedAt: Long?, val startPage: Int?, val endPage: Int?, val durationSec: Long?, val note: String?)
data class PhotoSnapshot(val fileName: String, val noteIndex: Int?, val createdAt: Long?)
data class ExtraField(val title: String, val value: String)
```

**Порядок заметок** (важен для привязки фото к заметкам) — единый для всех
форматов и **детерминированный**: группы `QUOTE` → `REVIEW` → `NOTE`, внутри
групы сортировка по `(createdAt ASC, id ASC)`. `PhotoSnapshot.noteIndex` —
индекс в этом списке (1-based).

Детерминированность важна для round-trip: при импорте заметки создаются в этом
же порядке, значит их `id` идут по возрастанию, а `createdAt` у всех новых
заметок одинаковый («now») — сортировка `(createdAt, id)` даёт тот же
порядок, и привязка фото к заметкам не сдвигается при повторном экспорте.

Новые файлы:

- `data/snapshot/LibrarySnapshot.kt` — модели;
- `data/snapshot/SnapshotBuilder.kt` — собирает снимок из БД (книги, заметки,
  сессии, теги, фото);
- `data/snapshot/SnapshotApplier.kt` — сливает снимок в БД (см. §7).

`SnapshotBuilder` читает: `bookRepository.observeAll()`, `noteDao.observeAll()`,
`sessionDao.observeAll()`, `photoDao.observeByBook(bookId)`, плюс **новый**
запрос в `TagDao`: теги книги (`SELECT t.* FROM tags t JOIN book_tags bt ON
bt.tag_id = t.id WHERE bt.book_id = :bookId`).

### 5.2 Промежуточная модель записи Tellico

`TellicoBookMapper` сейчас работает с `org.apache.commons.csv.CSVRecord`.
Вводим промежуточную модель, которую наполняют оба источника:

```kotlin
data class TellicoRecord(
    val fields: Map<String, String>,              // название поля → значение
    val extra: Map<String, ExtraField>,           // чужие поля: имя → (title, value)
)
```

Ключ словаря — **внутреннее имя поля Tellico** (`title`, `место-покупки`),
а не человеческий заголовок. Имя — то, чем поле называется в XML
(`<место-покупки>`), и именно оно кладётся в `<field name=…>` при экспорте,
поэтому `.tc` заполняет **существующие** поля коллекции, а не создаёт
дубликаты. Для CSV (там есть только заголовки) имя выводится по правилу
Tellico: `lowerCase`, пробелы → дефисы, недопустимые символы → дефис
(«Цена продажи» → `цена-продажи`, «livelib/fantlab» → `livelib-fantlab`).
Человеческий заголовок хранится рядом — он показывается в Tellico.

`TellicoBookMapper.map()` переезжает с `CSVRecord` на `TellicoRecord` и
возвращает `BookSnapshot` вместо `MappedBook`. Словарь «известных» названий
полей — тот же, что сейчас у маппера, плюс новые (§6). Всё, чего в словаре
нет, уезжает в `extra` — так чужие поля Tellico не теряются.

### 5.3 `TellicoCsvReader` (изменение)

`read(reader): List<TellicoRecord>` — вместо `List<CSVRecord>` собирает карту
«имя поля → значение». Заголовки CSV Tellico — это названия полей по-русски,
поэтому словарь маппера подходит. Колонки, которых в словаре нет («Чтец»,
«Посоветовал», «livelib/fantlab», «Цена продажи», «Дата продажи», «Редактор»,
…), попадают в `extra` — и сохраняются при экспорте.

Колонка «Номер» (Tellico-овский id записи) в `extra` **не попадает**: это
служебный id Tellico, а не пользовательские данные.

### 5.4 `TellicoXmlReader` (новый)

`read(bytes: ByteArray): List<TellicoRecord>` — разбирает `tellico.xml`:

1. **DOM-парсер** `javax.xml.parsers.DocumentBuilderFactory` (чистый JVM —
   тесты идут без Robolectric). Обязательно:
   - `load-external-dtd = false` — файл содержит DOCTYPE со ссылкой на DTD
     в интернете, сеть при импорте трогать нельзя;
   - `external-general-entities = false`, `external-parameter-entities = false`
     — защита от XXE;
   - `isExpandEntityReferences = false`, `setXIncludeAware(false)`.
   Фичи оборачиваем в `try/catch`: неподдерживаемая фича не должна ломать импорт.
2. Из `<fields>` собираем `имя поля → (title, columns)`. Признак табличного
   поля — `<prop name="columns">N</prop>`.
3. Выбираем коллекцию с `type="2"` (Book). Другие типы (фильмы, игры,
   библиография) — понятная ошибка «Это не коллекция книг»: у пользователя
   рядом лежат `Games.tc` (type 11) и `movi.tc` (type 3), а библиографии у
   него нет, и набор встроенных имён у неё другой (`year` вместо `pub_year`).
4. Каждый `<entry>` превращаем в `TellicoRecord`:
   - имя элемента → ключ:
     - **встроенное** имя → каноническое русское название (не зависит от
       языка интерфейса Tellico);
     - **пользовательское** поле → его `name` из `<fields>` (канонический ключ);
     если такого имени в словаре маппера нет — ищем по `title`, а если и его
     нет — то же название по правилу Tellico (`lowerCase`, пробелы → дефисы);
     - поле, которого нет в словаре маппера → в `extra` (имя + title).
   - встроенный `<id>` (id записи Tellico) **пропускается** — это служебное
     поле, а не пользовательские данные.
   - **контейнеры многозначных полей**: если у элемента есть контейнер
     `имя + "s"` с вложенными `имя`, берём их все:
     - обычное многозначное поле → `"; "` (как CSV-экспорт Tellico);
     - табличное поле (`columns > 1`) → `"\n"`: строки таблиц, склеенные в
       один список. Несколько таблиц в одном контейнере не теряются.
   - если контейнера нет — берём текст самого элемента (плоская форма);
   - даты приводим к ISO, но **частичные даты не выбрасываем**: `yyyy-MM-dd`,
     а если дня нет — `yyyy-MM`, а если нет и месяца — `yyyy`. Маппер дополняет
     недостающее до 1-го числа/января, так что «прочитано в 2023 году»
     сохраняется как 2023-01-01, а не теряется.

Таблица встроенных имён → ключи словаря маппера:

| XML | Ключ маппера |
| --- | ------------ |
| `title` | Заголовок |
| `subtitle` | Подзаголовок |
| `authors/author` | Автор |
| `publisher` | Издательство |
| `pub_year` | Год издания |
| `cr_years/cr_year` | Год сдачи в печать |
| `isbn` | ISBN# |
| `pages` | Количество страниц |
| `languages/language` | Язык |
| `genres/genre` | Жанр |
| `series` | Серия |
| `series_num` | Номер серии |
| `condition` | Состояние |
| `translators/translator` | Переводчик |
| `binding` | Переплёт |
| `pur_price` | Цена покупки |
| `pur_date` | Дата покупки |
| `read` | Прочитано |
| `gift` | Подарок |
| `loaned` | Одолжено |
| `rating` | Рейтинг |
| `cover` | Лицевая сторона обложки |
| `comments` | Аннотация |
| `cdate` | Создано |
| `mdate` | Изменено |

### 5.5 Маппер: `TellicoBookMapper` (изменение)

- `map(record: TellicoRecord): BookSnapshot`.
- **Статус** — три независимых булевых поля Tellico, приоритет при конфликте
  (в нашем экспорте конфликта не бывает: один статус → один флаг):

  | «Брошено» | «Прочитано» | «Прочитал часть» | Статус |
  | --- | --- | --- | --- |
  | да | — | — | ABANDONED |
  | — | да | — | FINISHED |
  | — | — | да | READING |
  | — | — | — | WISHLIST |

  «Прочитал часть» есть и в CSV, и в XML (в XML — пользовательское поле
  `прочитал-часть`), «Брошено» — наше поле `брошено`.
- **Цитаты** разбираются как строки табличного поля:
  - строка без префикса страницы → цитата без страницы;
  - `1:текст` (CSV) или `1::текст` (XML) → страница 1, текст `текст`;
  - строка из одних цифр (`4`) — «пустая» цитата, пропускается;
  - разделитель строк — только `\n`. Сейчас код режет ещё и по `;`, из-за чего
    цитата с точкой с запятой внутри разваливалась на две заметки. Правка
    приходит вместе с unification обоих путей.
  - страница кладётся в `NoteSnapshot.page` (колонка `notes.page` уже есть).
- **Даты и время** в таблицах: ISO `yyyy-MM-ddTHH:mm:ss` ↔ epoch millis.
- **Экранирование в табличных ячейках**: текст заметки может содержать
  перевод строки, а разделитель колонок — `::`. Поэтому при записи:
  `\` → `\\`, LF → `\n`, CR → `\r`. При чтении колонки делятся по `::`
  ограниченным числом (последняя колонка забирает остаток — «хвост» с
  `::` внутри значения не теряется), затем escape-последовательности
  разворачиваются обратно.
- Остальное поведение (ISBN, цены, `HtmlToMarkdown`) не трогаем: HTML-конвертер
  идемпотентен, поэтому «Аннотация»/«Рецензия» из XML (где `&lt;br/&gt;`
  после разбора становится `<br/>`) превращаются в markdown так же, как из CSV.

Принимает `List<TellicoRecord>`; старая перегрузка `invoke(input: Reader)`
остаётся как тонкая обёртка над CSV-ридером (её используют существующие

### 5.7 Экспорт: `books.csv` (изменение) — тоже без потерь

В существующий zip добавляются:

- `extra.json` — снимок всего, чего нет в CSV: заметки (с видом, страницей и
  `createdAt`), сессии чтения, теги, фото (имя файла в архиве + индекс
  заметки + `createdAt`), чужие поля Tellico;
- `photos/` — файлы фото заметок (как есть).

В `books.csv` добавляется колонка `id` (id книги в БД) — по ней
`extra.json` привязывается к строке, а не к позиции. Старые бэкапы без этой
колонки читаются как раньше (просто без `extra.json`).

Формат `extra.json`:

```json
{
  "books": {
    "620": {
      "notes":     [{"kind":"QUOTE","page":12,"body":"…","createdAt":1730000000000}],
      "sessions":  [{"startedAt":1730000000000,"endedAt":1730000600000,"startPage":1,"endPage":20,"durationSec":600,"note":"…"}],
      "tags":      ["фэнтези"],
      "photos":    [{"file":"photos/620_77.jpg","noteIndex":2,"createdAt":1730000000000}],
      "extraFields": {"посоветовал": {"t":"Посоветовал","v":"Книжный поезд"}}
    }
  }
}
```

### 5.8 Экспорт: `ExportTellicoTcUseCase` (новый)

Пишет `.tc`:

- `tellico.xml` — каталог `type="2"`, `title="kwbooktrack"`;
- `images/{md5}.{ext}` — обложки;
- `photos/{md5}.{ext}` — фото заметок (Tellico их не показывает, но они лежат
  в архиве и возвращаются при импорте).

Имя файла — **MD5 от содержимого** (ровно как у Tellico: `0dcebf7e….jpeg`).
Это не косметика: имя должно быть устойчивым между экспортом и повторным
импортом, иначе дедупликация фото по имени не сработает и при каждом
импорте появятся дубликаты. По содержимому — устойчиво всегда.

`<fields>`: объявляем **только свои (пользовательские) поля** — встроенные
Tellico знает сам (со своими типами и списками значений), а объявление
встроенного поля с другим типом может его испортить. Свои поля объявляем с
теми же `name` и `title`, что в коллекции пользователя, чтобы `.tc` заполнял
**её** поля, а не создавал дубликаты. Чужие поля (те, что приложение
переносит как есть) объявляем с сохранёнными `name`/`title`.

`category` обязателен (в DTD `#REQUIRED`) — значения взяты из коллекции
пользователя.

Свои и чужие поля объявляем **типом 1 (текст)**, кроме тех, где тип важен:
дата (`12`), флажок (`4`), таблица (`2` + `columns`), картинка (`10`),
рейтинг (`14`). Тип 3 (выпадающий список с фиксированным `allowed`) не
используем: у коллекции пользователя у «Места покупки» и «Языка оригинала»
списки жёсткие, и значение, которого в списке нет, Tellico при импорте в ту
же коллекцию потерял бы. Тип 1 принимает любое значение.

Поля, которые пишем (встроенные — имена Tellico, свои — из §6):

| XML | Что пишем | Куда в приложении |
| --- | ---------- | ----------------- |
| `title` | title | title |
| `subtitle` | subtitle | subtitle |
| `authors/author` | author (режем по `"; "`) | author |
| `publisher` | publisher | publisher |
| `cr_years/cr_year` | printYear | printYear |
| `pub_year` | year | year |
| `isbn` | isbn13 | isbn13 |
| `pages` | pageCount | pageCount |
| `languages/language` | language | language |

Для `rating` добавляем `<prop name="maximum">5</prop>` и
`<prop name="minimum">1</prop>`, для табличных полей — `column1…columnN` и
`columns=N`.

Правила записи:

- `<entry id="N">` — N сквозной, начиная с 1. Tellico при импорте добавляет
  записи как новые (режимы Append/Merge) либо заменяет коллекцию целиком
  (Replace) — свои id он при этом не наследует, поэтому пересечения с
  «Мои книги» не будет.
- **Многозначные поля — контейнерами** (как это делает Tellico, иначе значения
  не прочитаются): `<authors><author>…</author></authors>`,
  `<genres><genre>…</genre></genres>`,
  `<languages><language>ru</language></languages>`,
  `<translators><translator>…</translator></translators>`,
  `<cr_years><cr_year>…</cr_year></cr_years>`, а цитаты и свои табличные
  поля — `<цитатыs><цитаты>…</цитаты></цитатыs>`.
- Остальные поля — плоскими элементами.
- Даты — `<поле calendar="gregorian"><year>…</year><month>…</month><day>…</day></поле>`,
  месяц/день двузначные.
- Флаги статуса — как у Tellico: пишем только `true`, отсутствие = false:
  `<read>true</read>` при FINISHED, «прочитал-часть» при READING, «брошено»
  при ABANDONED. Значение `false` в файлах Tellico не встречается.
- `cover` — имя файла в `images/`; в `<images>` пишем
  `<image id="…" format="…"/>`, где `format` — по фактическому расширению
  файла (приложение хранит обложки как `.webp`, врать «jpeg» нельзя).
  `width`/`height` в DTD необязательны (`#IMPLIED`) — не пишем. Если обложек
  нет вообще, блок `<images>` не выводим вовсе: в DTD `images` требует хотя
  бы один `image`, пустой `<images/>` невалиден.
- `цитаты` — строки `страница::текст` (пустая страница → `::текст`).
- «Фото заметок» — строки `файл::индекс заметки::дата`, файл — путь внутри
  архива (`photos/<md5>.jpg`).
- `рецензия` — текст заметки REVIEW. Если у книги несколько рецензий, берём
  первую по `createdAt` (как это делает UI книги).
- `comments`/`рецензия` — текст как есть. Известное ограничение: приложение
  хранит markdown, Tellico ждёт HTML, поэтому в Tellico будут видны символы
  разметки (`**жирный**`). Конвертера markdown→HTML в проекте нет, а тянуть
  новую зависимость ради этого не будем.
- XML-экранирование `& < > " '` обязательно.

### 5.9 Миграция БД 8→9: хранение чужих полей Tellico

## 7. Семантика слияния при импорте

Выбрано пользователем: **слияние без дублей** — ничего не пропадает и ничего
не дублируется.

- **Книга**: поля перезаписываются импортом (как сейчас, через
  `upsertFromImport` — по ISBN либо по связке title+author). `source` не
  перезаписывается: `BookDao.upsertFromImport` сохраняет прежний.
- **Заметки**: добавляются только те, которых ещё нет (совпадение по
  `kind` + `body` + `page`).
- **Сессии**: добавляются только те, у которых нет совпадения по
  `startedAt`.
- **Теги**: `findOrCreate` + `attachToBook` (`insertCrossRef` — `OnConflictStrategy.IGNORE`),
  то есть объединение без дублей.
- **Фото**: добавляются только те, файла с таким именем ещё нет. Имя файла в
  архиве — MD5 от содержимого, поэтому оно устойчиво между экспортом и
  импортом и повторный импорт не плодит дубликаты.
- **Чужие поля**: значения в `books.extra_fields` **заменяются** импортом —
  это данные одного поля, «слияние» тут неуместно. Если поля в импорте нет,
  прежнее значение сохраняется (пустой импорт не стирает данные).

## 8. Что всё ещё теряется (осознанно)

- **Временные метки заметок** в `.tc`: у табличного поля Tellico нет
  даты на строку. В `books.csv`-бэкапе они сохраняются (`extra.json`) ✓, в
  `.tc` — нет (сохраняется только порядок заметок).
- **«Год сдачи в печать» с несколькими годами**: в данных одна книга имеет
  «1984; 1986; 1988», а в приложении поле `printYear` — одно число; берётся
  первый год. Расширять схему ради одной книги не буду.
- **`updatedAt` при повторном импорте в непустую библиотеку** обновляется
  («сейчас») — это общее правило импорта приложения (`BookDao.mergeWith`),
  книга встаёт вверх списка. `createdAt` при этом сохраняется, а при
  импорте в пустую библиотеку сохраняются оба (`<cdate>`/`<mdate>`).
- **`ABANDONED`** → при обратном импорте из чужого Tellico без поля «Брошено»
  станет `WISHLIST`.
- **`source`** (MANUAL/TELLICO/BOOKMORY/CATALOG) — при upsert сохраняется
  прежний, при создании новой книги ставится `TELLICO` (как сейчас).
- **Сессии/теги/фото** при импорте `.tc`, сделанного **самим Tellico**
  (а не нашим экспортом), не появятся — в Tellico таких полей нет.
- **Неизвестные поля Tellico** теряют свой *тип* (объявляются текстом);
  название и значение сохраняются полностью.
- **Поле «livelib/fantlab»**: в XML его имя `livelibfantlab`, а в CSV
  заголовок `livelib/fantlab` — из заголовка имя выводится как
  `livelib-fantlab`. Два разных имени → Tellico создаст второе поле. На
  остальные поля не влияет.
- **Markdown** в рецензии/аннотации Tellico покажет как есть (символы
  разметки видны): конвертера markdown→HTML в проекте нет, новую зависимость
  ради этого не тянем.

## 9. Ошибки

- Нечитаемый ZIP → понятное сообщение, импорт не падает на весь экран.
- ZIP без `tellico.xml` и без CSV → «в архиве нет ни tellico.xml, ни CSV».
- Некорректный XML → сообщение с причиной парсера.
- Коллекция не книжная (`type` не 1 и не 2) → «Это не коллекция книг».
- Отсутствующий файл фото → фото пропускается, импорт продолжается.
- Плохая обложка → как сейчас: лог + импорт продолжается.

## 11. Проверка «настоящим» Tellico

После реализации — прогон вручную:

1. Выгруженный `.tc` открыть в Tellico через **Import → Tellico Files**
   (фильтр Tellico принимает `*.tc` и `*.xml`) в режиме **Append** к «Мои
   книги» и в режиме **Replace**: поля на месте, обложки видны, чужие поля
   не превратились в дубликаты.
2. Отдельно проверить то, что unit-тесты поймать не могут:
   - поля, записанные **контейнерами** (`authors`, `genres`, `languages`,
     `translators`, `cr_years`, `цитатыs`), читаются как значения;
   - `<images>` без `width`/`height` — обложки показываются;
   - `format="webp"` в `<image>` совпадает с реальным файлом;
   - табличные поля «Заметки», «Сессии чтения», «Фото заметок» открываются
     в Tellico как таблицы.
3. `backup.tc` из той же коллекции разбирается приложением (обратный путь).
