# Родной формат Tellico (XML / .tc): импорт + экспорт — design

Date: 2026-11-05
Project: kwbooktrack (Android, Kotlin, Compose, Room, Hilt)
Status: одобрен пользователем (границы задачи), ожидает утверждения документа

## Goal

1. **Импорт**: приложение читает родной формат Tellico — XML (`tellico.xml` внутри
   `.tc`/`.zip`, либо сам `.xml`) — наряду с существующим импортом CSV. Формат
   определяется автоматически по содержимому файла, а не по расширению.
2. **Экспорт**: приложение умеет писать родной `.tc` (`tellico.xml` + `images/`),
   который Tellico открывает штатно. Это и есть синхронизация между программами:
   каталог уходит в Tellico и приходит обратно без конвертации руками.
3. Существующие пути не ломаются: импорт CSV из архива и собственный бэкап
   приложения (`books.csv` + `manifest.json` + `covers/`) продолжают работать.

## Non-goals (YAGNI)

- Не делаем импорт/экспорт **всех** типов коллекций Tellico (фильмы, игры,
  музыка). Только книги (`collection type="2"`) — то, что умеет приложение.
- Не переносим в Tellico сессии чтения и фотографии: в Tellico нет таких
  сущностей. Обложка — это единственная картинка, которая уезжает.
- Не импортируем чужие поля Tellico «как есть» (поля `livelibfantlab`,
  `посоветовал`, `чтец`, `иллюстратор`, `на анхол` и т.п.). Приложение их не
  знает — они молча теряются. Свои поля приложение знает и переносит.
- Не трогаем формат собственного бэкапа `books.csv`: он остаётся как есть.
  (Он, кстати, в Tellico не открывается: заголовки колонок английские и не
  совпадают с внутренними именами полей Tellico — ровно та проблема, которую
  и чинит эта задача.)

## Решения, зафиксированные в брейншторме

| Вопрос                                             | Ответ                                                          |
| -------------------------------------------------- | -------------------------------------------------------------- |
| Что входит в задачу                                | Импорт **и** экспорт в `.tc`                                   |
| Как называть нестандартные поля Tellico в `.tc`    | По-русски, как в коллекции пользователя («Место покупки» и т.д.) |
| Что кладём в `.tc` кроме книг                       | Книги + обложки + рецензии + цитаты                            |

## Формат Tellico — что выяснено

`.tc` — это **ZIP**. Внутри:

- `tellico.xml` — сам каталог (в бэкапе Tellico 4.x);
- `images/` — обложки (имя файла совпадает со значением `<cover>`); в более
  старых/других раскладках — `<collection>_files/`.

Структура `tellico.xml` (DTD: `http://periapsis.org/tellico/dtd/v12/tellico.dtd`):

```xml
<tellico xmlns="http://periapsis.org/tellico/" syntaxVersion="12">
 <collection title="Мои книги" type="2">
  <fields>
   <field category="Общее" flags="0" format="1" name="title" title="Заголовок" type="1"/>
   <field category="Покупка" flags="0" format="4" name="место-покупки" title="Место покупки" type="3"/>
  </fields>
  <entry id="1">
   <title>Властелин Колец</title>
   <authors><author>Толкин, Джон</author></authors>
   <genres><genre>фэнтези</genre><genre>эпическое фэнтези</genre></genres>
   <pur_date calendar="gregorian"><year>2023</year><month>08</month><day>04</day></pur_date>
   <read>true</read>
   <cover>0dcebf7e7711bd7154db82b21cac7f61.jpeg</cover>
   <comments>…HTML…</comments>
   <рецензия>…</рецензия>       <!-- пользовательское поле: имя как в title, в нижнем регистре -->
   <цитаты>1::текст цитаты
2::вторая</цитаты>              <!-- табличное поле: страница::текст, строки через \n -->
  </entry>
  <images><image format="jpeg" height="488" id="0dcebf7e….jpeg" width="310"/></images>
 </collection>
 <filters>…</filters>
</tellico>
```

Ключевые наблюдения:

- Внутри `entry` поля называются **внутренними английскими именами**
  (`title`, `authors/author`, `isbn`, `pages`, `languages/language`,
  `genres/genre`, `publisher`, `pub_year`, `cr_years/cr_year`, `series`,
  `series_num`, `condition`, `translators/translator`, `binding`, `pur_price`,
  `pur_date`, `read`, `gift`, `loaned`, `rating`, `cover`, `comments`), а
  **пользовательские поля — своими именами** (`место-покупки`, `дата-прочтения`,
  `рецензия`, `цитаты`, `продано-new`). Название поля (по-русски, заглавными)
  лежит в атрибуте `title` у `<field>`.
- **Многозначные поля (AllowMultiple, т.е. `flags & 1`) пишутся контейнером**
  `имя + "s"`, а значения — вложенными элементами `имя`:
  `<authors><author>Толкин, Джон</author></authors>`,
  `<genres><genre>фэнтези</genre><genre>эпическое фэнтези</genre></genres>`,
  `<languages>`, `<translators>`, `<cr_years><cr_year>1962</cr_year></cr_years>`,
  `<keywords><keyword>…</keyword></keywords>`.
  Поля без этого флага — плоские: `<publisher>`, `<series>`, `<binding>`.
  В коллекции пользователя `цитаты` тоже объявлены с `flags="1"`, поэтому
  Tellico пишет их как **`<цитатыs><цитаты>…</цитаты></цитатыs>`** — в одном
  контейнере бывает несколько таблиц (в реальных данных: 36 контейнеров, у
  шести — по 2–4 таблицы).
- Даты — либо `<поле calendar="gregorian"><year/><month/><day/></поле>`, либо
  текстом `2024-04-14` (у полей типа «дата, заданная строкой»).
- Табличные поля (цитаты) — `страница::текст`, строки разделены `\n`.
  В **CSV** тот же столбец пишется с одиночным двоеточием (`1:текст`).
- Многозначные значения в CSV Tellico пишет через `; ` — экспорт/импорт
  приложения должен вести себя так же.
- `<field>` требует `category` (в DTD `#REQUIRED`).

## Архитектура

Ключевая идея: **один маппер, два ридера**. Сейчас `TellicoBookMapper` работает
с `org.apache.commons.csv.CSVRecord`. Вводим промежуточную модель, которую
наполняют оба источника:

```kotlin
/** Одна запись Tellico: название поля (по-русски, как в CSV) → значение. */
data class TellicoRecord(val fields: Map<String, String>)
```

`TellicoBookMapper.map()` переезжает с `CSVRecord` на `TellicoRecord`
(один-в-один: `record.isMapped(name)` → `name in record.fields`,
`record.get(name)` → `record.fields[name]`). Всё остальное в маппере
(даты, bool, ISBN, цены, цитаты) не меняется.

### 1. `data/importer/TellicoCsvReader.kt` (изменение)

`read(reader): List<TellicoRecord>` — вместо `List<CSVRecord>` собирает карту
«заголовок колонки → значение». Заголовки CSV Tellico — это как раз названия
полей по-русски, поэтому словарь маппера подходит без изменений.

### 2. `data/importer/TellicoXmlReader.kt` (новый)

`read(bytes: ByteArray): List<TellicoRecord>` — разбирает `tellico.xml`:

1. **DOM-парсер** `javax.xml.parsers.DocumentBuilderFactory` (чистый JVM — тесты
   идут без Robolectric). Обязательно:
   - `load-external-dtd = false` — файл содержит DOCTYPE со ссылкой на DTD
     в интернете, сеть при импорте трогать нельзя;
   - `external-general-entities = false`, `external-parameter-entities = false`
     — защита от XXE;
   - `isExpandEntityReferences = false`, `setXIncludeAware(false)`.
   Фичи оборачиваем в `try/catch`: неподдерживаемая фича не должна ломать импорт.
2. Из `<fields>` собираем `имя поля → title` и свойства поля (`columns` —
   признак табличного поля). Нужно для пользовательских полей.
3. Выбираем коллекцию: берём первую с `type="1"` (Bibliography) или `type="2"`
   (Book). Другие типы (фильмы, игры, музыка) — понятная ошибка «Это не
   коллекция книг», а не тихий импорт мусора. У пользователя рядом лежат
   `Games.tc` и `movi.tc`, сценарий реальный.
4. Каждый `<entry>` превращаем в `TellicoRecord`:
   - имя элемента → ключ словаря маппера:
     - **встроенное** имя → каноническое русское название из таблицы ниже
       (не зависит от языка интерфейса Tellico);
     - **пользовательское** поле → его `title` из `<fields>`, а если такой title
       мапперу неизвестен — `name` поля, а если и он неизвестен — то же название,
       приведённое по правилу Tellico (`lowerCase`, пробелы → дефисы). Так
       «Дата прочтения» находится и по `title="Дата прочтения"`, и по
       `name="дата-прочтения"`.
   - **контейнеры многозначных полей**: если у элемента есть контейнер
     `имя + "s"` с вложенными `имя`, берём их все и склеиваем:
     - обычное многозначное поле → `"; "` (как CSV-экспорт Tellico), поэтому
       словарь маппера работает одинаково для обоих форматов;
     - табличное поле (`columns > 1`) → `"\n"`: строки таблиц, склеенные в
       один список. Несколько таблиц в одном контейнере не теряются.
   - если контейнера нет — берём текст самого элемента (плоская форма).
   - даты приводим к ISO `yyyy-MM-dd` (маппер уже умеет `dd.MM.yyyy` и ISO);
   - табличное поле «Цитаты» оставляем строкой — маппер разберёт строки.

Таблица встроенных имён → ключи словаря маппера:

| XML                                     | Ключ маппера          |
| --------------------------------------- | --------------------- |
| `title`                                 | Заголовок             |
| `subtitle`                              | Подзаголовок          |
| `authors/author`                        | Автор                 |
| `publisher`                             | Издательство          |
| `pub_year`                              | Год издания           |
| `cr_years/cr_year`                      | Год сдачи в печать    |
| `isbn`                                  | ISBN#                 |
| `pages`                                 | Количество страниц    |
| `languages/language`                    | Язык                  |
| `genres/genre`                          | Жанр                  |
| `keywords/keyword`                      | Ключевые слова        |
| `series`                                | Серия                 |
| `series_num`                            | Номер серии           |
| `condition`                             | Состояние             |
| `translators/translator`                | Переводчик            |
| `binding`                               | Переплёт              |
| `pur_price`                             | Цена покупки          |
| `pur_date`                              | Дата покупки          |
| `read`                                  | Прочитано             |
| `gift`                                  | Подарок               |

Пользовательские поля узнаются по названию: «Место покупки», «Дата прочтения»,
«Прочитал часть», «Продано?», «Усл. печ. л.», «Язык оригинала»,
«Оригинальное название», «Рецензия», «Цитаты».

### 3. `data/importer/TellicoBookMapper.kt` (изменение)

- `map(record: TellicoRecord)` вместо `map(record: CSVRecord)`.
- **Новое**: «Прочитал часть» = true → `BookStatus.READING` (иначе
  `Прочитано` → FINISHED, иначе WISHLIST). Поле есть и в CSV, и в XML
  (в XML — пользовательское поле `прочитал-часть`).
- **Новое**: цитаты разбираются как строки табличного поля:
  - строка без префикса страницы → цитата без страницы;
  - `1:текст` (CSV) или `1::текст` (XML) → страница 1, текст `текст`;
  - строка из одних цифр (`4`) → «пустая» цитата, пропускается;
  - разделитель строк — только `\n`. Сейчас код режет ещё и по `;`, из-за чего
    цитата с точкой с запятой внутри разваливалась на две заметки. Это общий
    для CSV и XML путь, поэтому правка приходит вместе с unification.
  - страница кладётся в `NoteEntity.page` (колонка уже есть в схеме).
- Остальное поведение маппера (даты, bool, ISBN, цены, `HtmlToMarkdown`) не
  трогаем: HTML-конвертер идемпотентен, поэтому «Аннотация»/«Рецензия» из XML
  (где `&lt;br/&gt;` после разбора XML становится `<br/>`) превращаются в
  markdown так же, как из CSV.

### 4. `data/importer/ImportTellicoUseCase.kt` (изменение)

Принимает `List<TellicoRecord>`; старая перегрузка `invoke(input: Reader)`
остаётся как тонкая обёртка над CSV-ридером (её используют существующие
тесты). Всё остальное — `persistCover`, `persistNotes`, счётчики — без изменений,
кроме того, что `persistNotes` теперь умеет писать страницу цитаты.

### 5. `data/importer/ImportTellicoZipUseCase.kt` (изменение) — авто-определение

Единая точка входа для файла, выбранного пользователем:

1. **Снапшот байтов** файла (первые 4 КБ достаточно, чтобы понять «PK» vs
   «<?xml»).
2. Если файл — **ZIP**:
   - ищем запись `tellico.xml` (в любой папке) → режим XML;
   - иначе ищем запись `*.csv` → режим CSV (как сейчас);
   - иначе — ошибка «в архиве нет ни tellico.xml, ни CSV».
   - **Приоритет у XML**: он родной, и в одном архиве могут лежать оба
     (в тестовом `tellico.zip` лежат и `tellico/tellico.csv`, и
     `tellico/Books.tc`; вложенный zip мы не распаковываем — CSV-путь
     продолжает работать как раньше).
   - Все картинки (`images/…`, `*_files/…`, любые `*.jpg|jpeg|png|webp`)
     раскладываются плоско в каталог обложек — как сейчас. Значение `<cover>`
     и ячейка CSV — это **голое имя файла**, поэтому плоская раскладка
     работает для обоих форматов.
3. Если файл — **не ZIP**:
   - начинается с `<?xml` / `<tellico` → режим XML (bare `.xml`);
   - иначе → режим CSV (bare `.csv`).
4. Дальше — общий путь: записи → маппер → БД.

Картинок у bare-`.xml` нет, поэтому обложки просто не скопируются — это
нормально, значение `<cover>` останется неразрешённым.

### 6. `data/exporter/ExportTellicoTcUseCase.kt` (новый)

Пишет `.tc`:

- `tellico.xml` — каталог `type="2"`, `title="kwbooktrack"`;
- `images/{bookId}.{ext}` — обложки (файл обложки копируется как есть).

`<fields>`: объявляем ровно те поля, которые пишем. Встроенные — с
объявлениями из коллекции пользователя (те же `type`/`format`/`flags` и
`category`), но без атрибута `allowed` (список допустимых значений у нас свой,
жёсткий список Tellico отбросил бы чужие значения). Пользовательские — с теми
же `name` и `title`, чтобы `.tc` заполнял **её** поля, а не создавал дубликаты:

| `subtitle` / Подзаголовок | 1 | 1 | 0 | Общее | subtitle |
| `author` / Автор | 1 | 2 | 7 | Общее | author |

| `оригинальное-название` / Оригинальное название | 1 | 4 | 0 | Общее | originalTitle |
| `рецензия` / Рецензия | 2 | 4 | 0 | Рецензия | заметка REVIEW |
| `цитаты` / Цитаты | 2 | 4 | 1 | Цитаты | заметки QUOTE |

`category` обязателен (в DTD `#REQUIRED`) — значения взяты из коллекции
пользователя, чтобы в Tellico поля легли в те же группы.

Пользовательские `место-покупки` и `язык-оригинала` объявляем **типом 1
(текст)**, а не 3 (список): у коллекции пользователя это выпадающие списки с
фиксированным `allowed`, и значение, которого в списке нет, Tellico при
импорте в ту же коллекцию потерял бы. Тип 1 принимает любое значение.

Для `rating` добавляем `<prop name="maximum">5</prop>` и
`<prop name="minimum">1</prop>`, для `цитаты` — `column1=страница`,
`column2=Цитата`, `columns=2` (как в коллекции пользователя).

Правила записи:

- `<entry id="N">` — N сквозной, начиная с 1.
- **Многозначные поля — контейнерами** (как это делает Tellico, иначе значения
  не прочитаются): `<authors><author>…</author></authors>`,
  `<genres><genre>…</genre></genres>`,
  `<languages><language>ru</language></languages>`,
  `<translators><translator>…</translator></translators>`,
  `<cr_years><cr_year>…</cr_year></cr_years>`, а цитаты —
  **`<цитатыs><цитаты>…</цитаты></цитатыs>`**.
  Значения `author`/`genre`/`translator` режем по `"; "` — в приложении это
  может быть склеенное значение после импорта CSV.
- Остальные поля — плоскими элементами.
- Даты — `<поле calendar="gregorian"><year>…</year><month>…</month><day>…</day></поле>`,
  месяц/день двузначные.
- Булевы — `true` / `false`.
- `cover` — имя файла в `images/`; в `<images>` пишем `<image id="…" format="…"/>`,
  где `format` — по фактическому расширению файла (приложение хранит обложки
  как `.webp`, врать «jpeg» нельзя). `width`/`height` в DTD необязательны
  (`#IMPLIED`) — не пишем. Если обложек нет вообще, блок `<images>` не выводим
  вовсе: в DTD `images` требует хотя бы один `image`, пустой `<images/>`
  невалиден.
- `цитаты` — строки `страница::текст` (пустая страница → `::текст`).
- `рецензия` — текст заметки REVIEW. Если у книги несколько рецензий, берём
  первую по `createdAt` (как это делает UI книги).
- `comments`/`рецензия` — текст как есть. Известное ограничение: приложение
  хранит markdown, Tellico ждёт HTML, поэтому в Tellico будут видны символы
  разметки (`**жирный**`). Конвертера markdown→HTML в проекте нет, а тянуть
  новую зависимость ради этого не будем.
- XML-экранирование `& < > " '` обязательно.

### 7. UI

- `ui/importer/TellicoImportScreen.kt`: кнопка «Выбрать файл» вместо «Выбрать
  ZIP-файл», mime-типы `application/zip`, `application/xml`, `text/xml`,
  `text/csv`, `application/octet-stream`, `*/*`. Описание — про `.tc`/XML/CSV.
- `ui/importer/TellicoImportViewModel.kt`: имя временного файла `tellico-…`
  → `import-…` (файл может быть не zip).
- `ui/about/AboutScreen.kt` + `AboutExportViewModel.kt`: в карточке «Резервная
  копия» — третья кнопка «Экспорт в Tellico (.tc)» с SAF `CreateDocument`
  (`application/zip`) и именем `kwbooktrack-tellico-<yyyy-MM-dd_HH-mm-ss>.tc`.
  Свой бэкап `books.csv` остаётся.

## Что теряется при экспорте в `.tc` (осознанно)

- Статус `ABANDONED` — в Tellico нет такого флага; при обратном импорте он
  станет `WISHLIST`.
- Сессии чтения, фотографии заметок, теги — в Tellico нет таких сущностей.
- Неизвестные Tellico-поля (`livelibfantlab`, `посоветовал`, `чтец`,
  `иллюстратор`, `на анхол`, `время-чтения`, `в-ближайших-планах`,
  `не-куплено`, `автор-родился`, `комикс`, `обложка`, `подписано`,
  `цена-без-бонусов`, `цена-продажи`, `дата-продажи`, `редактор`, `издатель`)
  при импорте в приложение отбрасываются — у приложения таких полей нет.
- `createdAt`/`updatedAt` в `.tc` не пишем: Tellico проставит свои при
  импорте, а field `cdate`/`mdate` — служебные.

## Ошибки

- Нечитаемый ZIP → понятное сообщение, импорт не падает на весь экран.
- ZIP без `tellico.xml` и без CSV → «в архиве нет ни tellico.xml, ни CSV».
- Некорректный XML → сообщение с причиной парсера.
- Коллекция не книжная (`type` не 1 и не 2) → «Это не коллекция книг».
- Плохая обложка → как сейчас: лог + импорт продолжается.

## Тестирование

- `TellicoXmlReaderTest` (чистый JUnit): разбор небольшого XML →
  ожидаемые значения в `TellicoRecord`:
  - контейнер `<authors><author>A</author><author>B</author></authors>` → «A; B»;
  - контейнер `<цитатыs>` с **двумя** таблицами → строки обеих таблиц в одном
    поле «Цитаты», строки разделены `\n`;
  - дата → ISO `yyyy-MM-dd`;
  - пользовательское поле — по `title` из `<fields>` и по `name`;
  - плоская форма (без контейнера) тоже читается.
- `TellicoBookMapperTest` (существующий): поправить хелпер на `TellicoRecord`;
  добавить кейсы «Прочитал часть» → READING, цитата со страницей, цитата без
  страницы, строка-пустышка `4` пропускается.
- `TellicoTcImportTest` (Robolectric): собрать во временном файле `.tc`
  (zip с `tellico.xml` + `images/x.jpg`) → импорт → книга, обложка, цитата,
  рецензия на месте.
- `TellicoTcRoundTripTest` (Robolectric): экспорт → импорт того же файла →
  те же книги/поля. Это главная гарантия «синхронизации между программами».
  **Важно:** наш импортёр и наш экспортёр симметричны и «согласованы» между
  собой, поэтому зелёный round-trip не доказывает, что файл поймёт Tellico.
  Единственная честная проверка — ручной прогон в Tellico (ниже).
- Существующие тесты (`TellicoImportIntegrationTest`,
  `TellicoZipImportRealTest`, `ImportKwBooktrackZipUseCaseTest`) должны остаться
  зелёными — они покрывают CSV-путь, который мы не ломаем.

## Проверка «настоящим» Tellico

После реализации — прогон вручную: экспортированный `.tc` положить в
`~/Документы/Tellico/kwbook/`, открыть Tellico, убедиться, что коллекция
создалась, поля на месте, обложки видны, а `backup.tc` из той же коллекции
разбирается приложением.

Отдельно проверить в Tellico то, что unit-тесты поймать не могут:

1. поля, записанные **контейнерами** (`authors`, `genres`, `languages`,
   `translators`, `cr_years`, `цитатыs`), действительно читаются как значения;
2. `<images>` без `width`/`height` — обложки показываются;
3. `format="webp"` в `<image>` совпадает с реальным файлом.
